# 企业微信 Bot 交互设计

## 交互原则

1. **对话即操作** — 用户发消息就是在操作，不需要菜单或表单
2. **确认再执行** — AI 生成的结果必须经用户确认才落库，避免自动化出错
3. **渐进披露** — Bot 回复先给结论，用户想看细节再展开
4. **出错可纠正** — 任何操作都可以在对话中说"改一下"来修正

## 消息类型

企业微信 Bot 支持的消息格式：

| 类型 | 用途 | 示例场景 |
|------|------|---------|
| 文本消息 | AI 回答、简单确认 | 回答"上月利润多少" |
| 图文卡片 | 凭证预览、发票摘要 | 展示 AI 生成的凭证 |
| Markdown | 报表数据、列表 | 进项税汇总、账龄清单 |
| 按钮交互 | 确认/修改/取消 | 凭证确认卡片 |
| 图片消息 | 接收发票照片 | 用户拍照发票 |
| 文件消息 | 接收/发送 CSV/Excel | 银行流水导入、报表导出 |
| 模板卡片 | 结构化信息展示 | 税务计算结果 |

## 场景 1: 自然语言记账 (US-1.1)

### 用户输入
```
付了3000块买办公用品
```

### Bot 回复（图文卡片）
```
📒 记账凭证 #2026-04-0012

日期：2026-04-07
摘要：购买办公用品

  借：管理费用 - 办公费     ¥3,000.00
  贷：银行存款             ¥3,000.00

[✅ 确认入账]  [✏️ 修改]  [❌ 取消]
```

### 修改流程
```
用户：改一下，是现金付的

Bot：
📒 记账凭证 #2026-04-0012（已修改）

日期：2026-04-07
摘要：购买办公用品

  借：管理费用 - 办公费     ¥3,000.00
  贷：库存现金             ¥3,000.00
       ~~~~~~~~ 已修改

[✅ 确认入账]  [✏️ 继续修改]  [❌ 取消]
```

### 确认后
```
Bot：✅ 凭证 #2026-04-0012 已入账。
```

## 交互模式总结

| 场景 | 触发方式 | 输入 | 输出 | 确认机制 |
|------|---------|------|------|---------|
| 记账 | 用户发消息 | 自然语言 | 凭证卡片 | 按钮确认 |
| 批量记账 | 用户发消息 | 多笔描述 | 凭证列表 | 全部/逐条确认 |
| 发票入账 | 用户发图片 | 发票照片 | 识别结果+凭证 | 按钮确认 |
| 批量发票 | 用户发多张图片 | 多张照片 | 处理进度+汇总 | 批量确认 |
| 进项查询 | 用户发消息 | 自然语言 | 税额汇总 | 无需确认 |
| 认证跟踪 | Bot 主动推送 | — | 未认证清单 | 标记已认证 |
| 银行对账 | 用户发文件 | CSV/Excel | 匹配结果 | 逐条确认 |
| 查报表 | 用户发消息 | 自然语言 | 数据+分析 | 无需确认 |
| 增值税 | 用户发消息 | 自然语言 | 计算结果 | 无需确认 |
| 抵扣筹划 | Bot 主动推送 | — | 优化方案 | 按钮确认 |
| 申报数据 | 用户发消息 | 自然语言 | 汇总+Excel | 导出确认 |
| 一致性检查 | 用户发消息 | 自然语言 | 异常清单 | 逐项处理 |
| 应收提醒 | Bot 主动推送 | — | 到期清单 | 按钮操作 |
| 所得税 | 用户发消息 | 自然语言 | 计算结果 | 无需确认 |

### 产出物类型

| 产出 | 格式 | 存储 |
|------|------|------|
| 会计凭证 | 结构化数据 | PostgreSQL |
| 发票记录 | 结构化数据 + 原图 | PostgreSQL + OSS |
| 余额调节表 | 结构化数据 | PostgreSQL，Web 端查看 |
| 财务报表 | 结构化数据 | PostgreSQL，Web 端查看/导出 |
| 税务申报数据 | Excel 文件 | OSS，企微文件消息发送 |
| 一致性检查报告 | 结构化数据 | PostgreSQL，Web 端查看 |
| 对话记录 | 消息日志 | PostgreSQL（含 token 追踪） |
